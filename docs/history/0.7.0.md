# 0.7.0 —— 真全屏、Termux 长跑运行时与 Minecraft 联机

> 一句话：这一版把「浮窗最大化」升级为**真正的独立全屏页面**，
> 把 Termux / Root / Shizuku 从「协议骨架」升级为**可追踪、可读取、可取消的长期运行时**，
> 并落地第一个高权限官方插件——**Minecraft 联机助手**（服务器 + AI 控制的 Mineflayer bot）。

---

## 一、整体变化

### 1. G6：真正的 FullscreenActivity

- 全屏不再给悬浮窗叠加 Flag，而是新增独立 `FullscreenActivity`；
- 进入全屏时把**同一个 WebView**从 WindowManager 迁移进 Activity，聊天/任务/音乐状态全部保留；
- 退出全屏时归还 WebView 并恢复悬浮窗原矩形；
- 沉浸式状态栏、edge-to-edge、返回键退出全屏，均已在代码层落地。

### 2. G8：Termux / Root / Shizuku 真实运行时

**Termux 长跑能力（核心）：**

| 能力 | 实现 |
|---|---|
| run_id 追踪 | 每个任务生成唯一 ID，落在该任务工作区 `.termux-jobs/` |
| 输出捕获 | wrapper 脚本将 stdout/stderr 重定向到 `runId.log` |
| PID 追踪 | wrapper 写 `runId.pid` |
| 状态查询 | `getJobStatus(runId)` → running / done / failed |
| 流式读取 | `readJobOutput(runId, offset)` → 支持增量读取 |
| 取消 | `cancelJob(runId)` → 信号文件机制（见下） |
| 列表 | `listJobs(taskId)` |
| 长跑支持 | 不设超时，服务器 / bot 可连续运行 |

- **白名单执行器**：python、node、git、rg、ffmpeg、**java**、**bash**（后两个是 Minecraft 前置）；
- **取消机制**：App 与 Termux 是不同 UID，App 无法直接 kill Termux 进程，改为
  **信号文件**——App 创建 `.cancel`，wrapper 检测到后先 SIGTERM 再 SIGKILL 子进程；
- **Root**：新增 `list_processes` / `kill_process`；
- **Shizuku**：检测应用是否安装、服务是否运行，`shizukuAuthorized` 反映真实状态（此前恒为 false）。

### 3. Minecraft 联机助手（首个高权限官方插件）

插件市场新增 `com.elly.market.minecraft`（v0.2.0），提供 12 个工具：

- `minecraft_setup` / `minecraft_install_deps` / `minecraft_deploy_bot`
- `minecraft_download_server` / `minecraft_start_server` / `minecraft_server_status` / `minecraft_stop_server`
- `minecraft_start_bot` / `minecraft_bot_command` / `minecraft_bot_status` / `minecraft_bot_chat` / `minecraft_bot_stop`

**Bot 如何进游戏：** Mineflayer 直接实现 Minecraft 网络协议，不需要第二个客户端，
一个 `npm install mineflayer` 即可让 bot 以普通玩家身份连入服务器。

**Bot 如何被 AI 控制：** 双向文件通道，构成「感知 → 决策 → 执行」闭环：

```text
AI → cmd.json（结构化指令）→ bot 执行 → cmd.result.json（结果）
bot → status.json（位置/血量/饥饿/背包/附近玩家，500ms 更新）
bot → chat.log（聊天记录）
```

支持动作：`say / move / look / lookAt / dig / digAt / place / attack / attackNearest /
activate / equip / toss / pathfind / pathfindToPlayer / stop / jump`。

**自主性：** bot.js 只是「执行层」，决策权在 AI——AI 先读 `status.json` 了解自身处境，
自行决定下一步，再发指令，然后回读状态形成循环，而不是跑固定脚本。

### 4. 横屏适配修复

- `FloatService` 新增 `onConfigurationChanged`：屏幕旋转后按新屏幕尺寸重新夹持窗口矩形与迷你条位置；
- 修复「横屏（玩游戏）时打开浮窗被卡在顶部一列、无法缩放」的问题。

### 5. 编译修复

- 修复 `TermuxWorker` 中 wrapper 脚本的 shell 变量在 Kotlin 三引号字符串内被误当作
  Kotlin 插值（`Unresolved reference: CANCELFILE / PIDFILE / CHILD / ...`）的问题，
  统一改用 `${'$'}` 转义。

### 6. 签名可复现（本版新增，重要）

**问题根源：** 项目此前没有自有 keystore，`release` 直接复用 `signingConfigs.debug`，
签名来自构建机自动生成的 `~/.android/debug.keystore`。而 **debug keystore 是每台机器/
每个环境各自随机生成的**，不同环境签出来的证书必然不同 → 覆盖安装时报
「更新包与已安装应用的签名不一致」。

**修复方案：** 新增项目自有固定 keystore，`debug` 与 `release` 共用它：

| 文件 | 作用 |
|---|---|
| `android/keystore/elysia.jks` | 项目专用签名密钥（别名 `elysia`） |
| `android/keystore.properties` | 指向该 keystore 的路径与口令 |
| `app/build.gradle` | `signingConfigs.elysia`，同时用于 debug 与 release |

这样**任何环境**（本机 / 沙箱 / CI）构建出的 APK 签名完全一致，后续版本升级不再冲突。

**新旧签名指纹对照：**

| 版本 | 证书主体 | SHA-256 |
|---|---|---|
| ≤ 0.6.5（历史） | CN=Android Debug | `43f9fb56…`（各机器不同，不可复现） |
| 0.7.0（本版起） | CN=ElysiaFloat | `7851cb49…`（固定，可复现） |

> ⚠️ **一次性注意**：由于历史版本用的是随机 debug 签名、且其私钥已不可获得，
> 从旧版（`43f9fb56…`）升级到本版（`7851cb49…`）时**需要卸载旧版再安装**，
> 或先备份应用数据。从本版起，之后所有版本之间可直接覆盖安装。
