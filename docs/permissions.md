# 权限与安全边界

ElysiaFloat 的能力由三层共同决定：Android 系统权限、应用内开关、原生策略校验。模型、提示词和插件都不能绕过其中任何一层。

## 1. Agent 能力等级

| 等级 | 能力 | 依赖 |
|---|---|---|
| L1 | 读取无障碍节点文字、查询已安装应用、读取浏览器地址 | Agent 总开关、L1、无障碍服务 |
| L2 | 截屏、识屏、限时观察屏幕变化 | Agent、L1、L2、无障碍截屏或系统截屏授权 |
| L3 | 点击、按文字点击、滑动、输入、系统按键、启动应用 | Agent、L3、安全开关、无障碍服务 |

- L1 只负责「看」和「查询」，不等于可以操作；
- L2 只提供画面，不自动执行动作；
- L3 才涉及操作，且启动或操作应用必须通过应用白名单。

## 2. 应用白名单

- 白名单以 Android **包名**为键，保存在原生配置中；
- 前端、提示词、插件都不能写入或伪造白名单；
- `find_app` 只负责查询真实应用；查询成功不代表允许操作；
- `launch_app` 与设备操作会在每次调用时重新检查白名单、当前前台应用、等级与安全开关。

## 3. 任务授权与逐次确认

从 0.7.2 起，安全确认按「任务 + 能力」授权，而不是每次操作都弹窗：

- 进入工作区或手机任务时确认一次，授权 **30 分钟**内有效；
- 任务结束、任务删除或应用重启后授权立即失效；
- 授权只保存在内存中，不写入磁盘，不上传；
- 授权只对当次任务有效，不会迁移到新建任务。

以下操作**始终逐次确认**，不受任务授权影响：

- 输入或提交密码；
- 支付、转账等资金操作；
- 卸载应用；
- 发送消息；
- 删除文件或目录。

## 4. 文件权限

Android 的「允许管理所有文件」只是系统层面的准入，应用内部还有额外边界：

- 工作区固定为 `Documents/ElysiaFloat/workspace`，是 Agent 的受控写入范围；
- 工作区外可访问公共存储，但每次访问都做路径规范化校验；
- 拒绝目录穿越与公共存储根目录之外的路径；
- 工作区写入在授权有效期内免逐次确认，并在写入前生成快照；
- 公共存储的写入、复制、建目录在授权有效期内合并确认一次；
- 公共存储的删除始终逐次确认；
- 文件类工具要求 Agent 等级、安全开关与文件权限同时满足；
- 插件声明不能绕过上述确认或原生策略。

## 5. 截图与观察

- 截图优先使用无障碍截屏，失败时回退到系统截屏授权；
- 截图和限时观察前，悬浮窗会收起或临时隐藏，减少对目标画面的遮挡；
- `watch_screen` 有时长、采样频率与帧数上限，不提供后台无限观察。

## 6. 插件权限

插件遵循「声明—授权—调用校验」模型：

- 安装不等于授权，启用插件时用户需要确认权限与风险；
- 每次工具调用都会重新检查插件状态、权限、Android 条件、Agent 策略、白名单和文件确认；
- JS 插件运行在独立 sandbox 中，不能访问 `Android` 桥、宿主 DOM、宿主存储或其它插件；
- 远程市场只在用户主动同步时获取 HTTPS 索引，并在安装前校验清单、ID/版本与 SHA-256；
- 哈希、信任标签和审核状态都不等于安全保证。

## 7. 数据与隐私

- API Key、聊天记录、长期记忆、任务记录保存在设备本地；
- 除用户配置的 AI 服务商、插件与音乐源外，应用不会主动上传内容；
- 插件审计只记录插件 ID、工具名、来源和时间，不记录参数、文件正文或消息内容；
- 屏幕内容、网页内容和文件内容都视为不可信数据，不会被当作指令执行。

## 8. 已知边界

- 无障碍能力受目标应用自身限制，部分应用会拒绝节点读取或文本设置；
- 不同厂商对后台保活、截屏和公共存储的实现存在差异；
- 应用不会自动修改系统默认输入法。
