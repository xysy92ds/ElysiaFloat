# ElysiaFloat 未来规划：多模式助手、工作 Agent、插件平台与外部 Agent 适配

更新时间：2026-10-07
状态：0.6.2 基础能力、插件市场、屏幕快捷操作和文档已完成；下一阶段不是继续给单一聊天循环堆功能，而是重构为“聊天与助手能力 + 手机 Agent + 工作 Agent + 可插拔运行时 + 外部 Agent 适配”的分层平台。

> 本文是实施规划。读完后应能明确：产品如何分层、设置如何组织、任务如何运行、工作区如何隔离、Agent 如何提速、插件如何分类、Root/Shizuku/Termux 如何接入，以及未来如何适配 DSH 等外部 Agent。

---

## 1. 总体目标

ElysiaFloat 最终应同时服务两类用户：

1. **普通用户**：不需要理解 Agent、工具调用、L1/L2/L3、工作区等概念，也能完成聊天、放歌、翻译、总结、图片理解和文件阅读等一般功能；
2. **高级用户**：可以明确创建和管理手机控制任务、长期工作任务、文件项目、Termux 任务、插件和外部 Agent。

总体原则：

- 普通聊天与复杂 Agent 彻底分开；
- 短任务与长任务分开；
- 手机控制与工作文件处理分开；
- 聊天人设只保留一个“自定义”入口，不设计预设风格选项；
- 视觉风格继续保留当前粉色、圆角、头像、悬浮窗、小球和胶囊设计；
- 设置页面重做信息架构，不再把所有开关堆在一页；
- 工作任务有独立 ID、上下文、目录、状态、日志和产物；
- 插件权限不能绕过 Agent、白名单、Android 权限和用户确认；
- Root、Shizuku、Termux 是运行时后端，不直接暴露为无限制权限；
- 先完善自己的工作模式，再接入 DSH 等外部 Agent 管理层；
- 所有长任务都可查看、暂停、继续、停止和失败收敛。

最终产品分层：

```text
ElysiaFloat
├── 聊天与助手
│   ├── 基础对话
│   ├── 普通助手能力
│   └── 一次性快捷任务
├── 手机 Agent
│   ├── 读屏
│   ├── 截图和视觉识别
│   ├── 点击、滑动、输入
│   └── 白名单应用控制
├── 工作 Agent
│   ├── 工作区
│   ├── 文件整理
│   ├── 项目处理
│   ├── 长时间任务
│   └── Termux Worker
├── 插件平台
│   ├── 聊天插件
│   ├── 快捷任务插件
│   ├── 手机插件
│   └── 工作插件
├── 能力运行时
│   ├── Android 基础能力
│   ├── 无障碍
│   ├── Shizuku
│   ├── Root
│   └── Termux
└── 外部 Agent 适配层
    ├── DSH Adapter
    └── 其它 Agent Adapter
```

## 3. 产品模式划分

### 3.1 聊天与助手：普通用户默认使用

页面和产品文案统一使用“聊天与助手”，不使用“工具调用”或“基础 Agent”等技术名称。

说明：

> 日常聊天、文字处理和常用助手功能。不主动控制手机，也不会自动执行长期工作任务。

包含：

- 基础对话；
- 总结对话；
- 翻译文字；
- 音乐播放；
- 图片理解；
- 用户主动上传文件后的阅读；
- 记忆功能；
- 屏幕翻译、总结屏幕、提取要点、解释屏幕等一次性快捷任务。

普通助手能力的规则：

```text
用户主动提出
→ 识别任务
→ 一次或少量工具调用
→ 返回结果
→ 立即结束
```

普通助手不应默认：

- 连续点击多个控件；
- 自动打开多个应用；
- 自动发送消息；
- 持续观察屏幕；
- 读取整个工作区；
- 修改工作区文件；
- 创建长期任务。

### 3.2 短任务模式

用于：

- 放歌；
- 翻译屏幕；
- 总结屏幕；
- 提取要点；
- 解释当前页面；
- 一次性图片识别；
- 一次性文件处理。

执行要求：

- 独立于长任务 Agent；
- 有明确的任务级超时；
- 默认不保存为长期任务；
- 工具调用数量少；
- 完成后立即释放上下文和状态。

建议目标：

- 普通短任务：15 秒内；
- 读屏任务：20 秒内；
- 截图识别：30 秒内；
- 超过上限时快速说明原因，不继续无限等待。

### 3.3 手机控制 Agent

用于：

- 查询和启动应用；
- 读取屏幕；
- 点击文字或坐标；
- 滑动；
- 输入；
- 系统按键；
- 发送消息前的准备工作。

典型流程：

```text
理解目标
→ 检查 Agent 条件
→ find_app 查询真实应用
→ 检查白名单
→ 启动应用
→ read_screen
→ 执行一个动作
→ 等待页面变化
→ 再次读取验证
→ 必要时继续下一步
→ 高风险操作前请求确认
→ 完成或失败收敛
```

每次只执行一个主要动作，不能让模型一次性连续点击、输入和发送。

### 3.4 工作 Agent

用于：

- 工作项目；
- 文件整理；
- 批量处理；
- 代码分析和修改；
- 文档生成；
- 用户上传资料的长期处理；
- Termux 脚本或工具链；
- 可暂停、恢复和长期运行的任务。

工作 Agent 必须绑定一个工作任务和一个独立工作目录，不直接使用普通聊天上下文代替任务状态。

## 4. 任务舱和主界面规划

### 4.1 视觉设计保持不变

保留当前已经形成识别度的设计：

- 粉色主题；
- 圆角卡片；
- 爱莉希雅头像；
- 悬浮主窗；
- 悬浮小球；
- 小胶囊；
- 音乐迷你条；
- 底部输入框；
- 柔和粉白色背景。

要改的是信息架构和状态展示，不是彻底更换视觉语言。

### 4.2 顶栏调整

当前顶栏的“记忆、清空”等按钮过多，后续调整为：

```text
任务圆点 / 头像 / 当前模式 / 设置 / 最小化 / 关闭
```

- 记忆移入聊天菜单或“聊天与助手”；
- 清空移入聊天菜单并保留二次确认；
- 顶部显示当前模式，如“聊天”“手机控制”“工作任务”；
- 工作任务中显示任务名称，而不是只显示助手名称。

### 4.3 左上角任务圆点

左上角小圆圈作为“任务舱”入口，点击后显示：

```text
当前聊天
快捷任务
手机控制任务
工作任务
外部 Agent 任务
已暂停任务
新建工作任务
```

每个任务显示：

- 任务名称；
- 任务类型；
- 运行状态；
- 最后更新时间；
- 暂停、继续、停止和切换操作。

状态颜色：

- 绿色：已完成；
- 蓝色：运行中；
- 黄色：等待用户确认；
- 红色：失败；
- 灰色：已暂停。

### 4.4 主界面当前模式

聊天框顶部或头像旁显示：

```text
当前模式：聊天
```

可切换为：

```text
聊天
普通助手
手机控制
工作任务
```

新用户默认处于“聊天”。低风险的普通助手任务可以自动判断；进入手机控制或工作任务前，应显示模式确认或提供明显的切换入口。

快捷按钮根据模式动态变化：

- 聊天：翻译屏幕、总结屏幕、放歌、新建任务；
- 手机控制：读取屏幕、截图、停止操作；
- 工作任务：添加文件、查看任务、运行、暂停；
- 其它低频功能放入“更多”。

任务运行时，在输入框上方显示：

```text
正在整理资料 · 第 2 步 / 5 步
[查看详情] [暂停]
```

或：

```text
正在操作 QQ · 等待用户确认发送
[允许] [拒绝]
```

手机 Agent 主要设置：

- Agent 总开关；
- 关闭 / 只读 / 可操作模式；
- L1 读取设备；
- L2 截图和视觉；

### 5.6 工作 Agent 提示词

工作 Agent 提示词必须和自定义聊天人设分开。

分层结构：

```text
不可覆盖的系统安全规则
+ 用户工作偏好
+ 当前工作任务提示词
+ 工作插件补充提示词
+ 当前工作区状态
```

设置页面允许用户编辑：

```text
我的工作偏好：
例如：先规划再执行，修改文件前先说明，输出文件放入 output 目录。
```

不可覆盖区域明确展示：

- 不绕过文件确认；
- 不访问任务工作区外路径；
- 不执行未授权设备行为；
- 不泄露密钥和隐私数据；
- 不因为用户提示词而关闭安全策略。

### 5.7 工作区与任务

设置页面负责默认规则，具体任务从任务舱进入。

设置项包括：

- 默认工作区；
- 上传文件默认行为；
- 是否自动建立文件索引；
- 任务保留时间；
- 是否生成快照；
- 是否允许联网；
- 是否允许 Termux；
- 默认任务超时；
- 默认失败重试次数。

用户上传文件的默认行为建议提供：

```text
每次询问
放入当前工作任务
只发送到聊天
```

默认选“每次询问”，避免不同任务互相污染。

## 6. Agent 性能和可靠性重构

当前 Agent 慢和容易超时的主要原因：

1. 模型请求使用 `stream: false`，必须等整轮生成完成；
2. 工具调用逐个串行执行；
3. 每轮模型请求固定允许等待 60 秒；
4. `agentToolRounds: 0` 默认代表无限轮数；
5. 截图等待最长 45 秒；
6. 视觉模型失败时可能出现截图 → 视觉请求 → 普通模型重试的多次串联；
7. 每轮重复发送完整聊天历史、工具列表和工具结果；
8. 没有完善的重复动作检测、页面变化检测和任务级熔断；
9. 读取屏幕、动作执行、模型请求和任务取消没有统一的状态机；
10. 外部 API 或中转模型本身可能存在排队、工具调用不稳定和上下文处理慢。

和成熟 Agent 的差距主要体现在：

| 能力 | 当前问题 | 目标实现 |
|---|---|---|
| 模型响应 | 非流式 | 流式输出和流式工具状态 |
| 工具执行 | 全部串行 | 无依赖工具可并行，有依赖工具按序执行 |
| 轮数 | 默认无限 | 任务级上限 + 用户可调整 |
| 超时 | 主要是单请求超时 | 任务总超时 + 分阶段超时 |
| 截图 | 最长等待 45 秒 | 8～12 秒快速失败并回报原因 |
| 重复动作 | 缺少完整检测 | 相同工具/参数和页面无变化时熔断 |
| 上下文 | 每轮携带较多内容 | 按模式动态工具列表、摘要和裁剪 |
| 取消 | 主要停止前端循环 | 同时取消模型请求、工具和原生任务 |
| 状态 | 依赖消息历史 | 独立任务状态机和事件日志 |

### 6.1 推荐执行模式

采用“短计划 + 单动作 + 状态验证 + 有限重规划”：

```text
用户目标
→ 意图分类
→ 能力和权限检查
→ 规划 2～4 个短步骤
→ 执行一个工具
→ 读取真实状态
→ 判断成功、失败、确认或重新规划
→ 完成、暂停或失败收敛
```

不采用无限 ReAct 作为默认行为。

### 6.2 统一 Agent 状态机

建议实现：

```text
START
  ↓
UNDERSTAND_GOAL
  ↓
CHECK_CAPABILITIES
  ↓
PLAN_SHORT_STEP
  ↓
EXECUTE_TOOL
  ↓
VERIFY_STATE
  ├─ 成功且未完成 → PLAN_SHORT_STEP
  ├─ 完成 → COMPLETE
  ├─ 需要确认 → WAIT_USER
  ├─ 可恢复失败 → RETRY / REPLAN
  └─ 不可恢复失败 → FAILED
```

任务状态对象至少包含：

```json
{
  "taskId": "task-001",
  "mode": "device|quick|workspace|chat",
  "goal": "用户目标",
  "phase": "execute",
  "step": 2,
  "rounds": 2,
  "deadline": 0,
  "foregroundPackage": "",
  "screenHash": "",
  "lastAction": "",
  "lastResult": "",
  "status": "running"
}
```

### 6.3 任务级和分阶段超时

建议初始默认值：

```text
普通聊天：30 秒
快捷任务：15～30 秒
手机控制任务：60～90 秒
工作任务单次步骤：30～60 秒
工作任务总时长：由任务设置决定
模型单次请求：20～30 秒
读屏：2 秒左右快速返回
动作执行：3 秒
页面稳定等待：最多 2 秒
截图：8～12 秒
视觉识别：20～30 秒
```

任务总超时到达后，所有后续工具调用必须停止，不能只停止前端 while 循环。

### 6.4 页面变化和重复动作检测

每次设备动作前后生成页面摘要：

- 前台包名；
- 可见文字摘要；
- 可见控件数量；
- 页面文字 hash；
- 关键控件和边界。

规则：

- 第一次页面不变：允许短暂等待或一次重试；
- 第二次相同动作且页面不变：告诉模型动作可能失败；
- 连续重复动作：熔断并要求重新规划；
- 工具返回权限拒绝、白名单拒绝或空树：不重复重试。

### 6.5 动态工具暴露

不要每次把所有工具都传给模型：

| 模式 | 默认暴露工具 |
|---|---|
| 聊天 | 普通对话能力和少量无副作用工具 |
| 快捷任务 | 当前任务需要的工具 |
| 手机 Agent | `find_app`、读屏、动作和验证工具 |
| 工作 Agent | 工作区、文件、任务和允许的 Termux 工具 |

工具定义越少，模型选择越快，输入上下文越小，误调用越少。

## 7. 工作区和长任务设计

### 7.1 任务隔离目录

建议目录结构：

```text
Documents/ElysiaFloat/
├── workspace/
│   ├── tasks/
│   │   ├── task-20261007-001/
│   │   │   ├── task.json
│   │   │   ├── input/
│   │   │   ├── working/
│   │   │   ├── output/
│   │   │   ├── logs/
│   │   │   └── snapshots/
│   │   └── task-20261007-002/
│   ├── shared/
│   └── templates/
```

每个任务必须有独立的 `task.json`：

```json
{
  "id": "task-20261007-001",
  "title": "整理用户上传资料",
  "status": "running",
  "mode": "workspace",
  "workspace": "tasks/task-20261007-001",
  "agent": "elly",
  "permissions": {
    "readFiles": true,
    "writeFiles": true,
    "network": false,
    "deviceControl": false
  }
}
```

### 7.2 工作任务生命周期

```text
NEW
→ PLANNING
→ RUNNING
→ WAITING_USER
→ PAUSED
→ COMPLETED
→ FAILED
→ ARCHIVED
```

每个状态都应有明确的用户操作：

- 新建；
- 开始；
- 暂停；
- 继续；
- 停止；
- 重试；
- 打开工作区；
- 查看日志；
- 查看输出；
- 归档或删除。

### 7.3 上传文件流程

```text
用户上传文件
→ 选择发送到聊天 / 放入当前工作任务 / 每次询问
→ 复制到 task/input/
→ 记录元数据
→ 生成文件索引
→ 通知当前 Agent 有新文件
```

默认使用“每次询问”。不能把文件自动放入全局工作区，也不能让不同任务共享输入文件而不记录来源。

### 7.4 工作区安全

- 默认只访问当前任务目录；
- 工作区外路径必须额外授权；
- 文件写入、覆盖、复制、创建目录和删除逐次确认；
- 所有路径经过 canonical path 校验；
- 支持修改前快照；
- 支持失败回滚或恢复最近快照；
- 工作 Agent 不读取聊天之外的文件，除非用户明确添加；
- 工作插件不能自动获得手机控制能力。

## 8. 插件系统分层

现有 Manifest v1、权限校验、HTTP/JS 沙箱和市场机制继续保留，但增加插件用途分类。

### 8.1 聊天插件

适合：

- 翻译；
- 搜索；
- 文本处理；
- 天气；
- 音乐；
- 轻量网络请求。

限制：

- 不默认访问工作区；
- 不默认访问手机；
- 不创建长期任务；
- 应尽量在 1～2 次调用内结束。

### 8.2 快捷任务插件

适合：

- 屏幕总结；
- 图片处理；
- 文件转换；
- 一次性导出；
- 单次数据查询。

限制：

- 有任务级超时；
- 不保留长期状态；
- 只访问用户当前明确提供的数据。

### 8.3 手机插件

适合：

- 设备查询；
- 屏幕读取；
- 应用控制；
- 自动化辅助。

必须明确声明：

- 需要的 Agent 等级；
- 是否需要无障碍；
- 是否需要截图授权；
- 目标应用是否必须加入白名单；
- 用户取消和权限拒绝时的行为；
- 是否会产生高风险操作。

插件不能：

- 直接访问 `Android.*`；
- 修改白名单；
- 伪造包名；
- 绕过 L1/L2/L3；
- 直接取得 Root 或 Shizuku；
- 直接执行任意 shell。

### 8.4 工作插件

适合：

- 项目分析；
- 文件整理；
- 代码处理；
- 报告生成；
- 批处理和文档转换。

工作插件需要声明：

```json
{
  "pluginType": "workspace",
  "taskModes": ["workspace"],
  "requiresWorkspace": true,
  "supportsPause": true,
  "supportsProgress": true
}
```

工作插件只能访问当前任务工作区或用户明确授权的路径。工作插件的文件修改仍需逐次确认。

### 8.5 插件安装和执行流程

```text
安装
→ 清单校验
→ 来源与 SHA-256 校验
→ 显示插件类型和权限
→ 用户确认
→ 危险插件默认停用
→ 用户启用并授权
→ 每次调用重新检查状态、权限、Agent、白名单和文件确认
```

后续插件阶段：

- [ ] 独立签名根；
- [ ] 撤销状态；
- [ ] 服务端静态扫描；
- [ ] 依赖检查；
- [ ] 审核流水线；
- [ ] 可关闭、可确认、可回滚的插件自动更新；
- [ ] 插件配置 Schema 和版本迁移；
- [ ] 插件事件订阅机制。

## 9. Root、Shizuku、Termux 运行时

### 9.1 统一能力适配层

不要把 Root、Shizuku 逻辑散落在每个 Agent 工具中，建立统一运行时接口：

```text
CapabilityRuntime
├── NormalAndroidRuntime
├── AccessibilityRuntime
├── ShizukuRuntime
├── RootRuntime
└── TermuxRuntime
```

统一接口示例：

```kotlin
interface DeviceRuntime {
    fun readScreen(): Result<ScreenState>
    fun tap(x: Int, y: Int): Result<ActionResult>
    fun launchApp(packageName: String): Result<ActionResult>
    fun readFile(path: String): Result<FileResult>
    fun writeFile(path: String, text: String): Result<FileResult>
}
```

Agent 只请求能力，不直接关心后端是普通 Android、Shizuku 还是 Root。

### 9.2 能力升级顺序

```text
普通 Android
→ 无障碍 / MediaProjection
→ Shizuku
→ Root
```

使用更高权限不代表关闭应用层安全门禁。所有后端都继续经过：

- Agent 总开关；
- L1/L2/L3；
- 应用白名单；
- 工作区和路径限制；
- 用户确认；
- 操作日志；
- 插件权限；
- 任务超时和取消。

### 9.3 Shizuku

计划提供：

- 授权状态检测；
- 启动或跳转授权页面；
- 能力清单；
- 失效重连；
- 按工具逐项授权；
- 不允许插件直接调用 Shizuku Binder。

### 9.4 Root

计划提供：

- Root 状态检测；
- 受控 Root Worker；
- 命令白名单；
- 工作目录限制；
- stdout/stderr 分离；
- 单命令超时；
- 可取消进程；
- 完整操作日志。

禁止：

- 插件直接执行 `su`；
- 用户文本直接拼接成 shell；
- Root Worker 访问未授权路径；
- 通过 Root 绕过工作区和确认机制。

### 9.5 Termux

Termux 作为独立 Worker：

```text
ElysiaFloat
  ↕ 本地认证 RPC
Termux Worker
  ├── Python
  ├── Node.js
  ├── Git
  ├── ripgrep
  ├── ffmpeg
  └── 用户脚本
```

必须具备：

- 随机 session token；
- 随机端口或受控本地端点；
- 本机地址限制；
- 任务 ID；
- 工作目录限制；
- 命令和参数白名单；
- 输出大小限制；
- 进程超时和取消；
- stdout/stderr 分离；
- 任务日志。

禁止直接执行：

```text
sh -c "用户输入"
```

Termux Worker 只能运行结构化命令和已授权脚本。

## 10. 外部 Agent 管理层

必须在自己的聊天、手机 Agent、工作 Agent、工作区和调度器稳定后再实现。

### 10.1 统一 Adapter 协议

```json
{
  "id": "dsh",
  "name": "DSH",
  "version": "1.0.0",
  "transport": "termux",
  "entry": "dsh-agent",
  "capabilities": ["chat", "workspace", "shell"],
  "permissions": ["workspace.read", "workspace.write"]
}
```

ElysiaFloat 负责：

- 下载适配包；
- HTTPS 来源校验；
- SHA-256 校验；
- 版本兼容检查；
- 独立配置目录；
- Agent 注册；
- 权限展示；
- 启动、暂停和停止；
- 工作区绑定；
- 日志和结果导回；
- 卸载和清理。

### 10.2 DSH 本地化适配

第一批外部适配可以选择 DSH，但不要把 DSH 特殊逻辑写死到核心 Agent：

```text
ExternalAgentAdapter
└── DshAdapter
```

后续可加入：

```text
└── TermuxAgentAdapter
└── LocalModelAdapter
└── OpenHandsAdapter
└── CustomAgentAdapter
```

### 10.3 一键下载安全流程

```text
展示名称、来源、版本和权限
→ 用户确认
→ 下载
→ 校验 SHA-256 / 签名
→ 创建隔离目录
→ 写入配置
→ 注册 Agent
→ 首次启动再次确认
```

外部 Agent 不得默认读取：

- 主应用 API Key；
- 用户聊天全部历史；
- 其它任务目录；
- Android 原生桥；
- Root/Shizuku；
- 未授权的公共存储。

## 12. 暂缓事项和不可违反的边界

暂缓：

- Root；
- Shizuku；
- Termux；
- DSH 和其它外部 Agent 一键下载；
- 任意插件直接执行 shell；
- 默认允许所有应用；
- 无提示自动切换默认输入法；
- 用聊天人设覆盖安全规则；
- 用无限工具轮数作为默认策略。

不可违反：

- 不取消应用白名单；
- 不让插件直接访问 Android 桥；
- 不让插件直接修改白名单；
- 不让聊天模式默认读取工作区；
- 不让工作 Agent 默认读取所有用户文件；
- 不让 Root/Shizuku 绕过用户确认；
- 不把 API Key、Cookie、Token、设备信息和用户数据写入仓库、日志或 APK；
- 不将“哈希匹配”“审核状态”宣传成插件绝对安全；
- 不用模型提示词代替原生安全校验；
- 不在失败、权限拒绝或空屏幕结果上无限重试。

```text
→ 配置应用白名单
→ Agent 先读屏、再执行单步操作、再验证
→ 高风险动作等待确认
```

工作用户：

```text
点击左上角任务圆点
→ 新建工作任务
→ 创建独立工作区
→ 上传文件到 input
→ Agent 规划和执行
→ 用户查看进度、确认修改、暂停或继续
→ 在 output 查看产物
```

高级用户：

```text
开启 Termux / Shizuku / Root
→ 选择允许的能力
→ 工作 Agent 使用受控运行时
→ 任务日志记录过程
→ 需要时安装外部 Agent
→ DSH 通过 Adapter 接入，不污染核心系统
```

最终判断标准不是“功能越多越好”，而是：

> 普通用户只看到简单可靠的聊天与助手；高级用户可以逐步打开 Agent、工作区和运行时能力；每个任务知道自己能访问什么、正在做什么、为什么失败，以及如何停止和恢复。
