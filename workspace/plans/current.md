## 0. 阅读规则和状态标记

### 0.1 状态标记

- `[x] 已完成`：代码已实现，并且有自动测试或构建证据；如果还没真机验证，会另行标记 `[真机待验]`。
- `[~] 基础版/部分完成`：已经有骨架或局部实现，但还不能宣称完整功能完成。
- `[ ] 未实现`：还没有可用实现。
- `[真机待验]`：代码或构建已完成，但还没有在目标 Android 设备上确认。
- `[暂缓]`：按当前产品顺序故意不做，等待前置条件或用户指令。
- `[阻塞]`：受到外部条件阻塞，例如远程网络、系统授权或第三方服务。

### 0.2 当前执行约束

1. 先在本地完成和验证，不进行新的 Git 提交和远程推送。
2. 用户指定的第 1～15 步已经完成了基础骨架和阶段构建；第 16 步 DSH 具体适配暂不做。
3. 任何“已接入”必须区分：
   - 有 UI 入口；
   - 有数据模型；
   - 有本地协议/状态骨架；
   - 有真实执行；
   - 有真机验证。
4. 普通聊天必须始终可用；高级 Agent、工作区、Termux、Root、Shizuku 或外部 Agent 出错时，不能拖垮普通聊天。
5. 不用模型提示词代替原生权限、安全校验、路径限制和用户确认。

# 1. 产品目标和最终边界

## 1.1 产品目标

ElysiaFloat 要同时服务两类用户：

### 普通用户

不需要理解 Agent、工具调用、L1/L2/L3、工作区、Runtime 等概念，也可以：

- 普通聊天；
- 总结和翻译；
- 播放音乐；
- 理解图片；
- 阅读用户主动上传的文字文件；
- 使用屏幕总结、屏幕翻译等一次性功能；
- 修改头像、名称和自定义聊天人设。

### 高级用户

可以逐步启用：

- 手机读取和操作；
- 应用白名单；
- 独立工作任务；
- 工作区文件处理；
- 长任务暂停和恢复；
- Termux Worker；
- Shizuku/Root 运行时；
- 分类插件；
- 外部 Agent Adapter。

## 1.2 最终能力分层

```text
ElysiaFloat
├── 聊天与助手
│   ├── 基础对话
│   ├── 普通本体能力
│   └── 一次性快捷任务
├── 手机 Agent
│   ├── 读屏
│   ├── 截图和视觉识别
│   ├── 点击、滑动、输入
│   └── 白名单应用控制
├── 工作 Agent
│   ├── 独立工作任务
│   ├── 独立工作区
│   ├── 文件和项目处理
│   ├── 长任务调度
│   └── Termux Worker
├── 插件平台
│   ├── 聊天插件
│   ├── 快捷任务插件
│   ├── 手机插件
│   └── 工作插件
├── 能力运行时
│   ├── Normal Android
│   ├── Accessibility / MediaProjection
│   ├── Shizuku
│   ├── Root
│   └── Termux
└── 外部 Agent 适配层
    ├── 通用 Adapter
    ├── DSH Adapter（暂缓）
    └── 其它 Adapter
```

## 1.3 不做的事情

当前不把以下内容作为默认体验：

- 普通聊天自动控制手机；
- 普通聊天默认读取整个工作区；
- 普通聊天自动修改文件；
- 默认允许所有应用；
- 默认启用 Root、Shizuku、Termux；
- 插件直接执行任意 shell；
- 插件直接取得 Root/Shizuku 原始句柄；
- 用一条聊天人设覆盖系统安全策略；
- 用无限工具轮数作为默认方案；
- 在没有完整性校验和权限展示的情况下“一键下载”外部 Agent。

# 3. 用户信息架构和界面规范

## 3.1 主界面目标排布

```text
┌─────────────────────────────────────┐
│ 头像  名称  模式       音乐 设置 全屏 最小化 × │ 第一行
├─────────────────────────────────────┤
│  ●任务舱       翻译       总结       更多       │ 第二行
├─────────────────────────────────────┤
│                                             │
│                 聊天内容                    │
│                                             │
├─────────────────────────────────────┤
│ ＋  输入框                         发送      │
└─────────────────────────────────────┘
```

设计规则：

- 第一行只放身份和窗口级操作；
- 第二行只放任务入口和高频快捷操作；
- 低频操作放进“更多”；
- 记忆和清空不再长期占据顶栏；
- 当前模式始终可见；
- 任务执行中，在输入区上方显示进度、等待确认或暂停入口；
- 小窗口空间不足时，名称省略，不压缩关闭按钮的可点击区域。

## 3.2 设置目标结构

```text
设置
├── 当前状态
├── 个性化与聊天风格
├── AI 与模型
├── 聊天与助手
├── Agent 与工作台
├── 插件与工具
├── 权限与安全
├── 数据与备份
└── 关于与诊断
```

说明：

- “当前状态”负责回答“现在什么能用”；
- “个性化与聊天风格”只处理名称、头像、外观和一个自定义人设；
- “AI 与模型”包含主模型、视觉/识图模型、向量模型和网络测试；
- “聊天与助手”只展示普通用户能理解的能力；
- “Agent 与工作台”容纳手机 Agent、工作 Agent、提示词、工作区和调度；
- “权限与安全”负责系统权限和高风险策略；
- 保存是悬浮的全局操作，不再绑在长页面某一个区域；
- 返回对话是设置页面最底部的独立操作。

当前事实：设置仍然以一张长页面和折叠分区为主，完整“设置首页 + 子页面”还未实现，不能标记为完成。

## 3.3 返回行为

```text
任务舱打开       → 关闭任务舱
插件市场         → 插件管理
插件管理         → 设置
设置/音乐/记忆/翻译 → 聊天
其它设置子页面   → 上一级
```

实现要求：

- JS 页面按钮和 Android 系统返回走同一套 `handleBack()`；
- 不允许系统返回直接关闭应用而跳过当前页面；
- 如果有未保存设置，返回时提示“保存 / 放弃 / 取消”；
- 长任务运行时返回只离开页面，不自动停止任务；
- 任务舱、确认弹窗和编辑器优先消费返回事件。

# 4. 产品模式和权限边界

## 4.1 聊天与助手

用户文案：

> 日常聊天、文字处理和常用助手功能。不主动控制手机，也不会自动执行长期工作任务。

允许：

- 普通对话；
- 用户主动上传内容的阅读；
- 一次性总结、翻译、图片理解；
- 播放音乐；
- 读取已明确请求的当前屏幕信息；
- 记忆检索和在符合规则时保存记忆。

不默认允许：

- 连续手机操作；
- 自动发消息；
- 自动读取整个工作区；
- 修改或删除文件；
- 长时间观察屏幕；
- 建立长期工作任务。

## 4.2 快捷任务

生命周期：

```text
用户点击快捷按钮
→ 创建 QuickTask
→ 检查当前能力
→ 调用少量工具
→ 返回结果
→ 标记完成并释放任务上下文
```

目标时间：

- 普通短任务：15 秒以内；
- 读屏任务：20 秒以内；
- 截图/视觉：30 秒以内。

快捷任务超时后必须给出原因，不进入工作 Agent。

## 4.3 手机 Agent

生命周期：

```text
理解目标
→ 显示进入手机控制的提示
→ 检查 Agent、无障碍、L 等级、安全开关和白名单
→ 生成 2～4 个短步骤
→ 每次执行一个主要动作
→ 等待页面稳定
→ 重新读屏验证
→ 成功、重规划、确认或失败收敛
```

高风险操作包括：

- 发送消息；
- 删除或覆盖文件；
- 支付、购买或转账；
- 输入密码、验证码或隐私信息；
- 启动敏感应用；
- 执行 Root/Termux 命令。

高风险操作必须显示目标、内容、应用或路径和影响范围，并逐次确认。

## 4.4 工作 Agent

工作 Agent 必须拥有：

- 独立 `WorkspaceTask`；
- 独立任务目录；
- 独立权限集合；
- 计划和步骤；
- 事件日志；
- 中间产物；
- 暂停、恢复、停止和失败现场；
- 文件变更清单。

不能用普通聊天历史代替工作任务状态。

# 5. 全任务生命周期

所有任务统一经过以下流程，具体模式只改变能力和执行器：

```text
接收输入
→ 识别任务类型
→ 显示模式/风险
→ 用户确认或低风险自动进入
→ 创建任务
→ 检查能力、权限和上下文
→ 生成短计划
→ 执行一个工具或模型步骤
→ 读取真实状态
→ 验证结果
├─ 成功但未完成 → 下一步骤
├─ 完成 → 输出结果
├─ 需要确认 → WAITING_USER
├─ 可恢复失败 → RETRY / REPLAN
├─ 权限拒绝 → 立即结束并说明
└─ 超时/不可恢复 → 保存现场并失败收敛
→ 归档结果或等待用户继续
```

## 5.1 任务类型

```text
chat       普通聊天
quick      一次性快捷任务
device     手机控制任务
workspace  工作任务
external   外部 Agent 任务
```

## 5.2 任务状态

```text
NEW             新建
CLASSIFYING     判断类型
WAITING_MODE    等待模式选择
CHECKING        检查能力
PLANNING        计划中
RUNNING         执行中
WAITING_USER    等待用户确认
PAUSED          已暂停
REPLANNING      重新规划
COMPLETED       已完成
FAILED          失败
CANCELLED       已取消
ARCHIVED        已归档
```

## 5.4 暂停、停止和恢复

### 暂停

- 不再发起下一次模型请求；
- 不再启动新工具；
- 保存当前计划和步骤；
- 保存工具结果和工作区中间文件；
- 状态变为 `PAUSED`。

### 停止

- 取消模型请求；
- 取消插件调用；
- 停止截图等待；
- 停止 Termux/Root 子进程；
- 不再接受当前任务的后续工具回调；
- 状态变为 `CANCELLED`。

### 恢复

- 重新读取 `task.json`；
- 重新检查权限；
- 重新读取文件或当前屏幕真实状态；
- 不直接重复可能已经执行过的动作；
- 从最近一个可验证步骤继续。

# 7. Agent 性能和可靠性计划

## 7.1 当前已知慢点

1. 部分模型请求仍为非流式；
2. 工具调用主要串行；
3. 请求、工具和截图等待没有完全统一的任务取消；
4. 截图/视觉失败可能串联多次请求；
5. 每轮可能携带较多历史、工具定义和工具结果；
6. 页面变化、重复动作和连续失败收敛不完整；
7. 工作任务还没有独立调度器；
8. 外部 API、中转服务和模型排队时间不可控。

## 7.2 目标执行算法

```text
目标分类
→ 能力检查
→ 生成 2～4 步短计划
→ 只执行当前一步
→ 获取真实状态
→ 验证
→ 完成 / 确认 / 重试一次 / 重新规划 / 失败
```

不以无限 ReAct 为默认执行算法。

## 7.3 超时预算

初始目标值：

```text
普通聊天：30 秒
快捷任务：15～30 秒
手机任务：60～90 秒
工作单步：30～60 秒
模型单次请求：20～30 秒
读屏：约 2 秒
动作执行：约 3 秒
页面稳定等待：最多 2 秒
截图：8～12 秒
视觉识别：20～30 秒
```

所有超时必须由任务调度器统一管理，而不是只停止前端循环。

## 7.4 页面变化和重复检测

动作前后记录：

- 前台包名；
- 可见文字摘要；
- 节点数量；
- 页面文字 hash；
- 关键控件文本、ID、边界；
- 最近工具和参数摘要。

策略：

- 第一次不变：短等待或一次重试；
- 相同动作 + 页面再次不变：标记可能失败；
- 连续重复：熔断并要求重新规划；
- 权限拒绝、白名单拒绝、空树：不重复重试。

## 7.5 动态工具列表

| 模式 | 默认暴露 |
|---|---|
| 聊天 | 无副作用的少量能力 |
| 快捷任务 | 当前快捷任务所需工具 |
| 手机 Agent | `find_app`、读屏、动作、验证 |
| 工作 Agent | 当前工作区、文件、任务和已授权 Runtime |
| 外部 Agent | Adapter 声明且用户授权的能力 |

## 8.2 工作任务权限

每个任务创建时生成权限快照：

```json

  "deleteFiles": false,

```

权限改变必须记录事件，不能只改一个全局配置后让历史任务无感变化。

## 8.3 文件流程

```text

→ 校验结果
→ 记录变更
```

- 默认只访问当前任务目录；
- 任务外路径额外授权；
- 写入、覆盖、复制、建目录、移动、删除逐次确认；
- 所有路径 canonical 校验；
- 重要变更前快照；
- 失败可恢复最近快照；
- 不把 API Key、Cookie、Token 写入任务日志；
- 日志默认记录摘要，不记录完整敏感文件内容。

# 9. 插件平台规划


### 聊天插件

- 轻量文本、搜索、天气、音乐等；
- 不默认访问工作区或手机；
- 不建立长任务。

### 快捷任务插件

- 单次图片处理、屏幕总结、文件转换；
- 有短超时；
- 不保存长期任务状态。

### 手机插件

必须声明：

- 所需 Agent 等级；
- 无障碍/截图要求；
- 白名单要求；
- 高风险行为；
- 取消和拒绝时的行为。

### 工作插件

必须声明：

- 是否需要工作区；
- 可访问的目录范围；
- 是否支持进度；
- 是否支持暂停；
- 是否生成产物；
- 是否会修改文件。

## 9.2 插件不得绕过的门禁

每次调用重新检查：

```text
插件启用状态
→ 插件权限
→ 工具权限
→ 当前任务类型
→ Agent 能力
→ 应用白名单
→ 工作区路径
→ 用户确认
→ 任务超时
```

插件不得：

- 直接访问 `Android.*` 原始接口；
- 修改白名单；
- 伪造包名；
- 绕过 L1/L2/L3；
- 直接执行 `su`；
- 直接取得 Shizuku Binder；
- 直接执行任意 shell。

# 10. Runtime、Termux、Root 和 Shizuku

## 10.1 统一能力接口

Agent 只请求能力，不直接知道后端细节：

```kotlin
interface DeviceRuntime {
    fun readScreen(): Result<ScreenState>
    fun tap(x: Int, y: Int): Result<ActionResult>
    fun launchApp(packageName: String): Result<ActionResult>
    fun readFile(path: String): Result<FileResult>
    fun writeFile(path: String, text: String): Result<FileResult>
}
```

所有 Runtime 仍必须经过：

- Agent 总开关；
- L1/L2/L3；
- 应用白名单；
- 工作区和路径策略；
- 用户确认；
- 审计；
- 超时和取消。

## 10.2 Termux Worker

目标结构：

```text
ElysiaFloat
  ↕ 本地认证 RPC
Termux Worker
  ├── 结构化命令
  ├── 当前任务工作目录
  ├── stdout/stderr
  ├── 退出码
  ├── 超时/取消
  └── 日志
```

必须具备：

- 随机 session token；
- 本机地址限制；
- 任务 ID；
- 当前任务目录绑定；
- 执行器和参数白名单；
- 输出大小限制；
- 进程超时和取消；
- stdout/stderr 分离。

禁止：

```text
sh -c "用户输入"
```

## 10.3 Shizuku

计划：

- 检测安装和授权；
- 显示能力清单；
- 授权失效后停止调用；
- 按工具声明能力；
- 不向插件暴露 Binder；
- 仍受 Agent 和用户确认策略限制。

## 10.4 Root

计划：

- 受控 Root Worker；
- 命令/参数白名单；
- 任务工作目录限制；
- stdout/stderr 分离；
- 单命令超时；
- 可取消进程；
- 完整审计；
- 禁止用户文本直接拼接 shell。

详细评估与修补路线另见 [`market-assessment-and-repair.md`](market-assessment-and-repair.md)（市场定位、差距、R0～R7 阶段、量化指标）。

优先级已从“功能优先”调整为“地基优先、能力后置”：

```text
R0 工程解耦  前端拆模块 + 构建脚本，产物仍为单文件 index.html
R1 可验证性  行为测试 + Kotlin 单测 + CI，失败阻断
R2 调度器    状态机、统一取消、动作后验证强制化
R3 发布工程  签名、版本策略、校验、真机矩阵
R4 安全纵深  威胁模型、注入防御、危险动作意图复核
R5 能力扩展  文件格式、Termux L2、Runtime 路由、插件分级
R6 高权限    Shizuku、Root 扩展、自动开启无障碍、Termux L3
R7 生态      插件签名/撤销、外部 Agent（含 DSH，最后推进）
```

近期可直接执行项：

1. **真机 UI 验收**：确认小窗口、窄屏、字体缩放下，名称和任务标志不被截断；确认音乐/设置第二行可点击；确认“更多”弹层不被窗口裁剪；确认全屏按钮在真实浮窗环境可用或正确提示不支持。
2. **设置页收尾**：验证底部“返回对话 / 保存设置”固定栏不遮挡内容；验证保存后返回不会丢失输入；补充系统返回键和页面返回键的一致行为。
3. **任务舱 UI**：任务详情、工作区路径、当前阶段和产物入口已接入，继续补产物导出。
4. **P1 已收尾**：文件索引、写入前快照、`snapshots/index.json`、回滚（回滚前自动再备份）已实现；待真机验证两个并行工作任务互不混入。
5. **P2 已收尾**：运行令牌拒绝迟到回调已实现；待补截图、Termux 子进程、插件调用的统一取消，再评估流式输出。
6. **R0 启动**：开始拆分前端模块，保持构建与冒烟全绿。
7. **发布前**：重新跑冒烟、行为测试、Debug/Release 构建、`git diff --check`、真机矩阵和权限撤销测试；DSH 仍保持暂缓。
