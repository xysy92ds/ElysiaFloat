## 0. 计划目标

本计划不再以“功能数量”作为完成标准，而以以下闭环作为完成标准：

```text
问题有证据
→ 任务有依赖
→ 代码完成
→ 自动测试通过
→ Android 构建通过
→ 真机关键路径通过
→ 文档和产物同步
→ 才能进入下一阶段或标记完成
```

任何只完成 UI、协议、数据模型或骨架的工作，都只能标记为“基础版/部分完成”，不能标记为完整能力。

## 1. 不可改变的产品和安全边界

1. 普通聊天不自动控制手机、不自动读取整个工作区、不自动修改文件。
2. `QuickOperation` 不默认进入持久任务舱；只有用户主动保存才升级为 `AgentTask`。
3. 手机操作必须经过 Agent 等级、L3 安全开关、无障碍和目标应用白名单。
4. 工作区内的写入、覆盖、建目录免逐次确认（覆盖前自动留快照）；工作区外公共存储的写入、覆盖、复制、建目录、删除必须逐次确认，且确认不能永久授权。
5. 工作区默认是受控写入范围；工作区外路径必须额外校验和确认。
6. 插件不能获得 `Android.*` 原始桥、Root、Shizuku 或任意 shell；声明权限不等于授权。
7. Root、Shizuku、Termux 和外部 Agent 默认关闭，必须有原生门禁、审计和取消。
8. 屏幕、网页、文件内容一律是“不可信数据”，不能直接覆盖系统安全规则或变成模型指令。
9. 普通能力失败不能拖垮普通聊天。
10. Debug 包不能作为正式发布包；任何发布都必须有签名、校验值和真机记录。
11. 设备操作按能力组授权：同一任务的 tap/input/launch/read 首次确认后 30 分钟内复用，不再逐次弹窗；密码框、发送消息、支付、卸载、外部文件删除仍逐次确认。简化的是“问人次数”，不是原生门禁。

### G2-005 安全确认精简（用户 2026-10-20 要求，插入项）

状态：待做（先定规则，再改代码）

问题现象：

- 已经在工作任务里，说「帮我改手机」会命中 `classifyTask()` 的设备关键词，
  `routeTask('device')` 直接**新建一个手机任务**并弹「进入手机控制模式」，
  原工作区被留在后台；随后要写文件又得再建一个工作区，任务链断裂。
- 进入设备模式、截图、输入、每个点击都会重复弹确认，实际使用像在拆弹。

要改的规则：

1. **任务粘性**：当前是 `workspace`/`device` 持久任务时，新一轮消息不再因为关键词
   切换任务类型。设备动作在当前任务内以「设备阶段」执行，复用 G5 相位机。
2. **能力级授权 + 时效**：第一次进入设备阶段只确认一次，授权绑定
   `taskId + 能力组(tap/input/launch/read) + 过期时间（任务结束或 30 分钟，取先到者）`；
   同一任务、同一能力组内不再重复弹窗。
3. **工作区不重建**：设备阶段不新建任务；需要文件时复用当前任务工作区，
   没有工作区时才创建一次并记住，不在两个任务之间来回跳。
4. **保留强确认（不可简化）**：密码框输入、发送消息、支付/购买、卸载应用、
   外部存储路径的写入/覆盖/复制/删除、Root、Termux 执行，仍逐次确认。
5. **截图**：`agentAutoShot` 开启时，同一任务内不再重复确认；关闭时保持逐次确认。
6. **原生门禁不减少**：JS 只减少「问人」的次数，L3、无障碍、应用白名单、
   canonical 路径校验一律照旧，权限不足仍然拒绝。
7. **审计**：授权决定写 `consent_granted` 事件（taskId/capability/expiry/来源），
   不记录输入内容；撤销授权写 `consent_revoked`。

出口（自动 + 真机）：

- 同一工作任务内「打开应用 → 点搜索 → 输入 → 返回」只在首次弹一次确认，
  任务不切换、工作区不重建；
- 退出任务或重启后授权失效，再操作会重新确认；
- 密码框、外部文件删除、发送消息仍然弹确认；
- smoke 覆盖：`inPersistent` 时 `routeTask` 不切换类型、授权复用与过期、
  高风险动作仍然确认。

## 6. G3：统一 RequestManager

状态：已完成（G3-1~G3-4 全部落地；真机 302/L2 行为待验）

### 已确认策略（用户 2026-10-17 决定）

- 重试 2 次，退避 2s / 6s；429 退避 10s；401/403/400 不重试
- 模型单次超时 200 秒
- 响应上限：文本/JSON 8MB；音频独立通道（150MB）；截图单独处理
- 重定向允许任意域名、最多 5 跳；放宽开关挂在 Agent L2（G3-2 接入）
- 错误对外：友好文案 + 小字错误码
- 审计只记域名/状态码/耗时/错误码，绝不记 path、query、头、正文
- 分 G3-1~G3-4 推进；版本号暂不动

### G3-1（已完成）

- 新增 `00b-request.js`：`REQ_CODE`、`reqRequest`、`reqTransport`、`reqToken`、脱敏审计
- 原生 `JsBridge.requestEx`：跳数上限、协议校验、字节上限、`useCaches` 可控、归一错误码、meta 回传
- `nativeReq` 改为薄适配层，9 个模块一次性纳入统一策略
- `chatReq` / `chatReqTools` 使用 `expect: json` + 200s 预算 + 任务 deadline 继承
- 仓库内已无绕过 RequestManager 的裸 `Android.request(` 调用

### G3-2（已完成）

- 插件 HTTP 迁入（`source: plugin:<id>`，保留插件自带超时，错误码透传）
- 音乐 `musicRequest` 迁入，复用 `MUSIC_HEALTH`；重试降为 1 次（速度优先）
- 跨域跳转策略：`music:*` / `system:*` 始终允许；`plugin:*` / `agent*` 由 Agent L2 控制
- 原生逐跳 host 校验，`REDIRECT_ERROR`「跨域跳转被拒绝（Agent L2 未开启）」
- `musicStripVolatile()` 强制历史/队列/缓存/收藏不落短时签名直链

### G3-3（已完成）

- 更新检查、翻译、记忆向量、TTS 音色、识图、远程市场/插件安装全部迁入
- 仓库内已无模块直接调用 `nativeReq`（只剩 `00-compat.js` 兼容壳）

### G3-4（已完成）

- 全仓复查无裸请求；每个 `reqRequest` 调用点都带 `source`
- smoke 增加：错误码/重试/上限/取消/预算继承、跨域策略双向验证、直链不落盘、插件错误码透传

实现目标：

```text
RequestManager
├── requestId
├── taskId / cancelToken
├── timeout budget
├── cancel
├── retry policy
├── redirect policy
├── response size limit
├── MIME / schema validation
├── normalized error code
└── source health / redacted audit
```

统一错误至少包括：

```text
TIMEOUT
NETWORK_ERROR
HTTP_ERROR
AUTH_ERROR
REDIRECT_ERROR
PARSE_ERROR
NO_MEDIA
NO_TEXT
PERMISSION_DENIED
USER_CANCELLED
INVALID_ARGUMENT
```

出口：聊天、识图、翻译、音乐、插件、更新不再各自维护互相矛盾的请求规则。

## 15. 阶段完成定义

一个任务只有同时满足以下条件，才可以从“进行中”改为“完成”：

```text
实现代码
+ 自动测试
+ 构建成功
+ 关键真机路径
+ 文档同步
+ 未解决风险登记
```

如果只有代码或 UI，标记为“基础版”；如果只有本地构建，标记为“真机待验”；如果测试失败，标记为“阻塞中”。
