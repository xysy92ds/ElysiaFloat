# 0.13.0 插件长任务运行时 + MC 插件（E7）实施计划

更新时间：2026-10-29
状态：0.13.0 完成、0.13.1 代码完成（路线 B 桥接），待真机联调与发布
上游计划：[`PLATFORM-0.8-0.15.md`](PLATFORM-0.8-0.15.md) 10.6 / E7；[`MASTER-EXECUTION-PLAN.md`](MASTER-EXECUTION-PLAN.md)
用户决策：MC 先只做离线登录；手机玩 Java 版（PojavLauncher 等启动器）；**单手机全包**（游戏、bot、App 同一台手机，bot 连 `127.0.0.1`）；设备 Termux 已装但 Node 未装。

**路线决策（2026-10-29）：选 B「桥接」** —— 不自研决策循环，Termux 里跑现成引擎（Mindcraft-CE / minecraft-mcp-server），App 只做配置页、启停、状态/日志桥。影响：R-004 取消自造 token RPC，插件用已有的 `network.local` 访问本机 HTTP；M-004~M-011 降级为“引擎适配层”，不再逐条实现感知/动作/决策。

## 1. 结论

主计划把 0.13 定为 MC 插件，但插件运行时目前没有“长驻进程”能力：

- `run_termux_job` 只允许在 `workspace` 工作任务中调用，且每次派发都要用户确认；
- 插件权限表没有 `runtime.termux`，`PLUG_CAPABILITY_PERMS` 也没有映射 Termux 工具；
- 插件 JS 工具运行在 sandbox iframe 中，不能自己常驻、不能持有 Mineflayer 连接。

因此 0.13 拆成两小步：**0.13.0 先补插件长任务运行时**，**0.13.1 再做 MC 插件**。

## 2. 范围

### 做

- 插件声明并托管一个受控的 Termux 长驻进程（Node）。
- 宿主 ↔ 长驻进程的本地 RPC、健康检查、日志、停止与重启。
- npm / termux-pkg 依赖安装闭环（Node + Mineflayer）。
- MC 离线登录：连接、感知、动作、决策循环、聊天指令桥、断线恢复。
- 配置页（surface）与状态展示（只写日志/会话状态，不做独立面板）。

### 不做

- 微软正版登录、网易版、基岩版。
- 反作弊绕过、自动交易、自动加好友/群发。
- MC 独立大面板。
- 任意 shell 文本执行。

## 3. 0.13.0 插件长任务运行时（前置）

| ID | 任务 | 关键改动 | 验收 |
|---|---|---|---|
| R-001 | 权限模型 | 新增 `runtime.termux` 权限；`PLUG_CAPABILITY_PERMS` 映射 `run_termux_job / termux_job_status / termux_job_output / termux_job_cancel / termux_jobs_list`；仍要求 Agent 开关 + 工作任务 + 逐次确认 | 未声明权限的插件调用直接拒绝；声明后仍需用户确认 |
| R-002 | 清单 v2 `runtime` 块 | `{kind:"termux-node", entry, autostart, restart:"on-failure", healthcheckMs, logMaxBytes}`；校验入口路径必须在插件沙箱内 | 非法入口/越界路径拒绝安装 |
| R-003 | 宿主托管 | 为插件创建隐藏工作任务 `plugin.<id>.runtime`；首启用户确认一次，之后按 restart 策略自动拉起 | 启停、杀进程后按策略恢复 |
| R-004 | 本地 RPC（路线 B 简化） | 不再自造 token RPC：引擎自己监听 `127.0.0.1`，插件用已声明/已授权的 `network.local` + 安全开关访问；宿主只负责启停、状态与日志 | 未声明 `network.local` 的插件访问本机被拒；安全开关关闭时同样被拒 |
| R-005 | 依赖闭环 | “一键准备环境”：`termux-pkg nodejs` + `npm mineflayer`；复用 E5 lockfile、进度、日志、卸载回滚；Node 未装时给出可复制的 Termux 命令兜底 | Termux 已装但无 Node 的现状可一键补齐 |
| R-006 | 守护与观测 | 心跳、异常退避重启、日志轮转、停止/清理；接入 E6 预算与看门狗 | 长跑 30 分钟不泄漏；日志有上限 |
| R-007 | 示例插件 | `node-hello` 长驻插件（启动/心跳/回显/停止），作为回归夹具 | 自动门覆盖启停与断线重启 |

出口：示例 Node 长驻插件可装、可启、可停、可恢复；主聊天与其它插件不受影响。

**进度（2026-10-29）**：R-001 / R-002 / R-003 / R-005 / R-006 / R-007 已完成并有自动门（`smoke.js` 三条回归）。R-003 暂不做后台自动重启：`run_termux_job` 每次都要求用户确认，静默拉起等于绕过确认，需单独决策后再加“会话级授权”。R-005 复用 E5 依赖闭环（Termux 包 + npm 全局安装），Node 未装时给出可复制命令；R-006 完成心跳、失败退避（只报告不拉起）、原生 200KB + JS 按 `logMaxBytes` 双层轮转、停止清理。

真机联调（Termux 装 Node、开房间端口、实际进世界）仍未做。

## 5. 环境与前置

- 设备：Termux 已装，**Node 未装** → 先做 R-005 的“一键准备环境”，并提供手动命令兜底。
- 联调形态：**单手机全包**。PojavLauncher 开单人世界 → 对局域网开放 → bot 连 `127.0.0.1:端口`；端口每次随机，配置页支持粘贴 `Local game hosted on port xxxxx` 自动解析并记住上次。
- 单手机同时跑“集成服务器 + 玩家客户端 + Node bot”，建议 8GB 内存起步；联调时降低渲染距离、关光影，注意发热和掉帧。
- Android 后台会冻结 Termux/Node：需要 Termux wake lock、关闭电池优化，并由 App 前台服务托管 bot；游戏切后台也可能暂停世界。
- 原版 LAN 端口每次随机，自动发现（UDP 组播 `224.0.2.60:4445`）在 Android 上可能被过滤，配置页以手动 `IP:端口` 为可靠路径；要固定端口就改用专用服务器或改 `server-port`。
- Mineflayer 只支持 Java 版；局域网房间和 `online-mode=false` 的专用服务器都可离线进。
- 0.12 的 E5/E6/G8-001 只有自动门证据，没有真机验收；MC 联调前先跑一次最小 Termux 作业（`node -v`）。
- 长驻进程涉及保活与耗电，0.12 的前台服务/唤醒锁需在 MC 验收前确认。

## 7. 风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 插件无法长期持有连接 | MC 无法运行 | R-003/R-004 宿主托管 + 本地 RPC |
| Node 未装 | 无法真机联调 | R-005 一键安装 + 手动命令兜底 |
| 离线登录被服务器拒绝 | 连不上 | 仅允许自有 `online-mode=false` 服务器，配置页提示 |
| 单手机资源不足 | 游戏卡顿、bot 掉线、发热 | 降渲染距离；先做低配模式；保留“bot 移到电脑”的部署接口 |
| Android 后台冻结 | bot 停止响应 | 前台服务 + 唤醒锁 + 电池白名单；游戏保持前台 |
| 动作频率过高 | 服务器踢人/封禁 | 指令限频、动作节流、危险动作确认 |
| 0.12 基础未真机验收 | 问题叠加 | 先跑最小 Termux 作业冒烟，再进 MC |
