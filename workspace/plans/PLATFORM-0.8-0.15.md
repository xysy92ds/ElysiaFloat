用户同时明确：

1. 从 0.7.x 起**只发测试版**，小步迭代，不设 1.0 稳定版节点。
2. **聊天是首页**，这是聊天浮窗；管理面板只能是次级入口，不能把首页换成仪表盘。
3. **取消独立「确认中心」**，改为「本次会话自动确认」开关。
4. **QQ / MC 都是插件**，不是应用内置功能；MC 不单独做面板，QQ 做微型面板。
5. 插件平台的目标是**开放生态**，官方插件只是示例；人民群众可以自己扩展应用本身。
6. 应用自身能力必须保障：普通聊天、工作能力、文件、设备、音乐不能被插件平台改坏。
7. **插件必须能创建宿主没有的功能**：不能只从宿主预设的主题、会话、选项里挑；主题插件、恋爱游戏插件只是验收样例，不是能力上限。

## 1. 产品原则（不可违背）

1. **聊天第一**：打开浮窗永远是对话；面板、插件页、市场、设置都是可返回的次级页面。
2. **核心不回归**：每个版本必须通过核心路径回归（发送、粘贴、长按、横屏、工作区、设备、音乐、更新）。
3. **插件即生态**：不为官方插件写死入口；所有插件走同一套 Manifest、配置、面板、事件和权限。
4. **开放运行时**：宿主只提供原语（surface、组件、动作、事件、适配器），不预设插件类型；
   插件可以注册我们没写过的新页面、新会话、新组件、新后台任务、新模型/网关适配器。
5. **声明式优先**：0.10/0.11 的插件界面用结构化组件树描述，不能直接注入 DOM/CSS/JS 到宿主；
   0.15 再开放沙箱 HTML，仍走独立 WebView + postMessage。
6. **免更新扩展**：插件只用通用原语实现的新功能，不应要求宿主发版；宿主新增的只是原语，不是某个插件。
7. **会话级授权**：普通操作按会话自动确认；高风险动作仍逐次确认。
8. **故障隔离**：单个插件异常、卡死、组件错误不能拖垮聊天；未知组件降级渲染，插件可单独停用。
9. **默认关闭、可回滚**：新扩展点、插件主题、专属会话都可关闭、重置、卸载清理。
10. **安全边界不降**：插件拿不到 Android 桥、明文 Key、其它会话数据、任意 shell。

## 5. Epic 详细规划

### E1 体验与面板入口（0.9）

目标：保持聊天首页不变，把次级功能收进可返回的面板；把确认改成会话级。

- E1-001 聊天首页固定：启动、恢复、返回都落在对话；面板是抽屉/覆盖层。
- E1-002 面板入口：任务、插件、模型、运行时、日志、设置；返回栈不丢。
- E1-003 会话级自动确认（见第 6 节）。
- E1-004 设置拆分：AI 与模型 / 外观 / 权限 / 工作区 / 高级。
- E1-005 核心回归门：发送、粘贴、长按、横屏、工作区、设备、音乐、更新。
- E1-006 状态条：会话运行中显示心跳、当前目标、停止按钮，不遮挡输入区。

出口：首页永远是聊天；所有次级页面可返回；会话自动确认可用且高风险仍确认；核心回归全绿。

### E2 模型中心（0.9）

- E2-001 Provider 注册表：OpenAI-compatible、Anthropic、Gemini、自定义；导入/导出不含密钥。
- E2-002 能力标签：`chat` / `vision` / `image` / `video` / `embedding` / `tts` / `asr` / `code`。
- E2-003 用途绑定：聊天、识图、生图、视频、向量、插件默认模型。
- E2-004 密钥安全：Keystore + EncryptedSharedPreferences；迁移旧明文 Key；日志/导出/崩溃永不含密钥。
- E2-005 连接测试与能力探测：延迟、错误码、是否支持图片/工具。
- E2-006 插件配置档：插件可自带 Provider，或引用用户授权档；拿不到明文 Key。
- E2-007 主 AI 调度子模型：`generate_image` / `analyze_image` / `generate_video` 等宿主工具，带配额与确认。
- E2-008 用量与限额：按 Provider/任务统计调用、token、估算费用；超限暂停。
- E2-009 回退链：主模型失败自动切备用；能力不匹配切专用模型。

出口：新增 Provider 不改聊天代码；插件可选独立模型；密钥不出现在任何日志或导出。

### E3 插件运行时（0.10）

目标不是「支持主题/会话/选项」，而是**让插件注册宿主没写过的东西**。
宿主只提供原语和注册表，不预设插件类型；主题、恋爱游戏只是验收样例。

- E3-001 Manifest v2（兼容 v1）：顶层字段只有 `surfaces`、`permissions`、`dependencies`、`models`、`apiVersion`；
  具体功能全部由 `surfaces` 里的注册项描述，宿主不关心它叫什么。
- E3-002 Surface 注册表（开放）：
  - `page`：任意新页面/子页面，可挂到面板、设置、插件详情；
  - `entry`：任意新入口，可挂到聊天头部、底部工具栏、加号菜单、任务详情；
  - `sessionType`：任意新会话类型（名称、图标、人设、开场白、状态 Schema、钩子）；
  - `command`：任意聊天命令；
  - `event`：任意事件订阅（消息、会话、定时、依赖、任务、网关）；
  - `job`：任意后台任务/定时任务；
  - `settings`：任意设置分区；
  - `renderer`：任意命名渲染模板；
  - `adapter`：模型 / 网关 / 文件 / 媒体适配器（0.15 开放实现）。
- E3-003 通用组件树：插件返回结构化组件，不写 HTML/CSS。
  `layout` / `text` / `stat` / `button` / `input` / `select` / `list` / `table` / `image` /
  `progress` / `chart` / `tabs` / `modal` / `choice` / `form` / `divider` / `spacer`。
  未知组件一律降级为占位，不阻塞渲染。
- E3-004 通用动作：`navigate`、`plugin.call`、`config.set`、`state.set`、`session.create`、
  `session.delete`、`message.send`、`theme.apply`、`confirm`、`openUrl`、`clipboard.write`、
  `job.schedule`、`dependency.install`、`custom`。动作由宿主校验权限后执行。
- E3-005 数据绑定：`{{state.*}}`、`{{config.*}}`、`{{session.*}}`；插件只提交数据，不操作 DOM。
- E3-006 配置 Schema：string / number / boolean / enum / secret / path / model-ref / json；
  自动生成配置表单，AstrBot 式插件专属配置页。
- E3-007 生命周期：install / enable / disable / uninstall / on_load / on_unload / on_event / on_job。
- E3-008 Host API：`host.surface`、`host.config`、`host.state`、`host.session`、`host.panel`、
  `host.log`、`host.model`、`host.dependency`、`host.job`。
- E3-009 私有存储：配置、状态、会话数据按插件命名空间隔离；带 Schema 版本与迁移。
- E3-010 权限与隔离：每个 surface/action 绑定权限；插件异常只影响自身；可单插件停用。
- E3-011 AstrBot 对齐 ADR：采用清单/配置页/生命周期/事件/私有存储；不采用任意 Python 执行。

出口：新增一个「宿主从没写过」的插件页面、入口、会话类型、命令、后台任务，**不需要改宿主代码**；
v1 插件不迁移可运行；单插件崩溃不影响聊天。

### E4 插件 UI 运行时（0.11）

目标：让插件用通用原语**组合出我们没做过的界面和行为**，而不是从固定功能里选。

- E4-001 挂载点注册表：`chat.header`、`chat.footer`、`chat.message.after`、`chat.composer.before`、
  `panel.home`、`panel.tabs`、`settings.section`、`session.create`、`task.detail`、`notification`；
  插件可声明任意挂载点 + 排序 + 显示条件。
- E4-002 通用样式白名单：颜色、背景、渐变、圆角、边距、字号、字重、透明度、阴影、
  背景图（宿主解析资源）；不接受任意 CSS，不允许 `url()` 注入。
- E4-003 主题包：插件可定义多个主题包，每个包是一组样式令牌 + 背景资源；
  可全局或单会话应用，可预览、可重置。
- E4-004 会话类型引擎：插件定义状态 Schema、开场、每轮钩子、渲染模板、结束条件；
  宿主负责创建/删除/隔离，插件只操作自己的命名空间。
- E4-005 渲染模板：插件可注册命名模板，在消息后、会话头、面板卡片、任务详情等位置复用。
- E4-006 每轮交互：`choice` 组件支持 A/B/C + 自定义输入；也可渲染表单、滑块、卡片、列表；
  自定义输入始终保留，插件不能锁死输入框。
- E4-007 设置扩展：插件可增加任意设置分区，复用配置 Schema 与动作系统。
- E4-008 卸载清理：删除插件会话、主题、配置、依赖、定时任务，需用户确认。
- E4-009 插件开发者工具包：模板仓库、清单校验、组件树校验、动作权限检查、本地加载调试、示例集。
- E4-010 沙箱 HTML 面板：0.15 开放，独立 WebView、独立 origin、无 Android 桥、仅 postMessage。

出口：三个验收场景必须通过：

1. **主题插件**：任意背景图 + 任意配色/圆角/字号组合，可预览、可重置，聊天不受影响。
2. **恋爱游戏插件**：创建可删除的专属会话，AI 每轮换背景、渲染选项/表单，状态可保存，卸载可清理。
3. **陌生功能插件**：一个宿主从未设计过的功能（例如「番茄钟 + 专注统计页 + 聊天头部计时器 + 定时提醒」），
   只用 surface + 组件 + 动作 + job 实现，宿主零改动。

### E5 依赖与运行时（0.12）

- E5-001 依赖声明：`termux-pkg` / `npm` / `archive` / `binary` / `apk`；版本、来源、SHA-256、体积、许可证。
- E5-002 检测：命令、版本、目录完整性。
- E5-003 下载与校验：HTTPS、SHA-256 必填、失败清理临时文件。
- E5-004 安装：插件沙箱或 Termux prefix；lockfile；不写系统目录。
- E5-005 卸载与回滚：按 lockfile 逆序；失败恢复上一版本。
- E5-006 依赖面板：缺什么、为什么、来源、体积、许可证、进度、日志。
- E5-007 APK 依赖：只能走系统安装器 + 用户确认，禁止静默安装。
- E5-008 Termux/Node 引导：检测 Termux、`RUN_COMMAND`、proot；缺失给安装指引。
- E5-009 运行时桥：固定命令模板 + 白名单；超时、取消、输出限制、审计；插件不能传任意 shell。

出口：Node、Mineflayer、NapCat 三类依赖可检测/安装/卸载/回滚；无哈希不安装；无任意 shell。

### E6 持久会话与长时运行（0.12）

- E6-001 `PersistentSession`：目标、计划、阶段、进度、预算、检查点、心跳。
- E6-002 看门狗：进程、网络、模型、依赖、前台服务异常时指数退避重启；超限转暂停。
- E6-003 前台服务 + 活动期间 partial wake lock；常驻通知可见，随时停止。
- E6-004 检查点：定期写磁盘；重启后恢复。
- E6-005 调度器：间隔、定时、条件触发（电量/网络/游戏状态）。
- E6-006 预算与熔断：时长、token、动作数、费用；超限暂停而非失败。
- E6-007 日志轮转：按会话分文件、限制总大小、脱敏导出。
- E6-008 保活引导：电池白名单、通知渠道、厂商自启动设置。

出口：息屏 8 小时会话不丢；杀进程可恢复；随时可停；耗电与流量有统计。

### E7 MC 插件（0.13）

定位：第一个「平台能力验证插件」，不是应用核心；**不做专属面板**。

- E7-001 清单与配置：服务器地址、版本、正版/离线、白名单、行为边界。
- E7-002 依赖：Node + Mineflayer，由 E5 安装与检测。
- E7-003 感知：方块、实体、背包、血量、坐标、聊天。
- E7-004 动作：移动、挖掘、放置、合成、容器、攻击/躲避、聊天、跟随。
- E7-005 决策循环：目标分解、失败重试、卡死检测、危险回避、饥饿/死亡恢复。
- E7-006 游戏内指令桥：聊天命令 → 会话指令；频率与权限限制。
- E7-007 长时运行：接入 E6，断线重连、死亡恢复、服务器重启恢复。
- E7-008 安全：仅用户自有/授权服务器；不绕过反作弊；不自动交易。
- E7-009 状态展示：只写日志与会话状态，不做独立面板。

出口：30 分钟连续任务（采集 → 返回 → 存放）稳定；断线重连；游戏内指令 2 秒内响应。

### E8 QQ 插件（0.14）

## 6. 会话级自动确认（替代确认中心）

用户明确：不想再专门打开确认中心。

### 6.1 交互

- 位置：会话头部 / 任务状态条，一个开关「本次会话自动确认」。
- 默认：关闭。
- 有效期：本次会话结束、手动关闭、应用重启后失效。
- 指示：开启时状态条显示醒目标记，随时可关。
- 不持久化：不写入设置，不跨会话继承。

### 6.2 自动确认范围

覆盖普通能力组：

- 点击、输入、启动应用、读屏；
- 截屏；
- 工作区内写入、覆盖、建目录；
- 公共存储的写入、复制、建目录（合并为一次）；
- 插件会话内的选项点击与普通 UI 动作。

### 6.3 仍逐次确认（不可自动化）

- 密码框输入；
- 发送消息到外部应用/联系人；
- 支付、购买、充值；
- 卸载应用；
- 删除公共存储文件或目录；
- Root / Termux 命令执行；
- 安装依赖 / 安装 APK；
- 插件申请全局主题、创建/删除专属会话、卸载清理数据。

### 6.4 审计

写 `consent_auto_enabled` / `consent_auto_disabled` / `consent_action` 事件，记录 taskId、能力、结果，不记录输入内容。

## 7. 插件运行时规范（开放生态的核心）

### 7.1 设计目标

宿主不认识「主题插件」「恋爱游戏插件」「番茄钟插件」这些类型。
宿主只认识四类原语：

```text
Surface（挂什么） + Component（长什么样） + Action（点了做什么） + Adapter（接什么外部能力）
```

插件负责把这些原语组合成任意功能。只要组合得出，宿主就不需要发版。

### 7.2 Surface 注册表

| Surface | 作用 | 可挂载位置 |
|---|---|---|
| `page` | 任意新页面 | 面板、设置、插件详情、深链 |
| `entry` | 任意新入口 | 聊天头部、底部工具栏、加号菜单、任务详情 |
| `sessionType` | 任意新会话类型 | 新建会话、会话切换 |
| `command` | 任意聊天命令 | 聊天输入、外部网关 |
| `event` | 任意事件订阅 | 消息、会话、定时、依赖、任务、网关 |
| `job` | 任意后台/定时任务 | 调度器 |
| `settings` | 任意设置分区 | 设置页 |
| `renderer` | 任意命名渲染模板 | 消息、会话头、面板卡片、任务详情 |
| `adapter` | 模型/网关/文件/媒体适配器 | 0.15 开放 |

Manifest 示例：

```json
{
  "manifestVersion": 2,
  "apiVersion": 1,
  "id": "com.example.focus",
  "surfaces": {
    "pages": [{ "id": "stats", "title": "专注统计", "body": [ /* 组件树 */ ] }],
    "entries": [{ "id": "focus", "mount": "chat.header", "label": "专注", "action": { "type": "navigate", "surface": "stats" } }],
    "sessionTypes": [{ "id": "focus-room", "name": "自习室", "state": { "minutes": 0 }, "hooks": ["onTurn"] }],
    "jobs": [{ "id": "tick", "every": 60, "action": { "type": "plugin.call", "tool": "tick" } }]
  },
  "permissions": ["ui.page", "ui.entry", "ui.session.create", "job.run"]
}
```

### 7.3 通用组件树

插件提交 JSON 组件树，宿主用设计系统渲染；不接受 HTML/CSS。

```json
{
  "type": "layout",
  "direction": "column",
  "children": [
    { "type": "stat", "label": "今日专注", "value": "{{state.minutes}} 分钟" },
    { "type": "progress", "value": "{{state.progress}}" },
    { "type": "row", "children": [
      { "type": "button", "label": "开始", "action": { "type": "plugin.call", "tool": "start" } },
      { "type": "button", "label": "重置", "action": { "type": "confirm", "then": { "type": "plugin.call", "tool": "reset" } } }
    ] },
    { "type": "table", "columns": ["日期", "时长"], "rows": "{{state.history}}" }
  ]
}
```

组件库：`layout`、`row`、`text`、`stat`、`button`、`input`、`select`、`list`、`table`、
`image`、`progress`、`chart`、`tabs`、`modal`、`choice`、`form`、`divider`、`spacer`。
未知组件降级为占位；单个组件报错只影响该组件。

### 7.4 通用动作

| 动作 | 作用 | 需要的权限 |
|---|---|---|
| `navigate` | 打开插件页面/面板分区 | `ui.page` |
| `plugin.call` | 调用插件自己的工具 | 无（插件内） |
| `config.set` / `state.set` | 写配置/状态 | 插件命名空间 |
| `session.create` / `session.delete` | 创建/删除专属会话 | `ui.session.create` |
| `message.send` | 在插件会话里发消息 | `chat.send` |
| `theme.apply` | 应用主题包/样式 | `ui.theme.session` / `ui.theme.global` |
| `confirm` | 请求用户确认后再执行 | 无 |
| `openUrl` / `clipboard.write` | 打开链接/写剪贴板 | `net.open` / `clipboard.write` |
| `job.schedule` | 注册定时/后台任务 | `job.run` |
| `dependency.install` | 安装声明过的依赖 | 安装确认 |
| `custom` | 交给插件处理并返回新状态 | 插件内 |

动作由宿主校验权限、频率和参数后执行；插件不能直接调用 Android 桥。

### 7.5 会话类型引擎

插件只声明，宿主负责创建与隔离：

- 名称、图标、简介、开场白；
- 状态 Schema 与初始值；
- 钩子：`onCreate`、`onUserMessage`、`onTurn`、`onAction`、`onDelete`；
- 每轮渲染模板与可选 `choice` / `form`；
- 结束条件与可删除标记；
- 数据命名空间。

插件不能读取其它会话、主聊天记忆或系统提示词的安全段。

### 7.6 适配器注册（0.15）

插件可以实现宿主没有的外部能力，只要遵守统一接口：

- `model`：列模型、聊天、识图、生图、视频、TTS；
- `gateway`：消息平台连接、收发、事件；
- `file`：新格式解析/导出；
- `media`：搜索、解析、播放源。

适配器运行在沙箱；密钥由用户配置，插件拿不到明文；调用计入配额。

### 7.7 插件如何做出「我们没有的功能」

| 例子 | 只用原语实现 | 宿主改动 |
|---|---|---|
| 番茄钟 | `entry` 挂聊天头部 + `page` 统计 + `job` 每分钟 tick + `message` 提醒 | 0 |
| 自定义主题商店 | `page` 列表 + `theme.apply` + 图片资源 | 0 |
| 恋爱游戏 | `sessionType` + `renderer` + `choice` + `theme.apply` | 0 |
| 新的模型 Provider | `adapter.model` + 配置 Schema（0.15） | 0 |
| 新的消息平台 | `adapter.gateway` + `sessionType`（0.15） | 0 |
| 新的文件格式 | `adapter.file` + `entry`（0.15） | 0 |
| 新的小游戏 | `sessionType` + 组件树 + `state` + `job` | 0 |

这就是「开放出去，让人民群众发挥创造力」的落点：宿主提供积木，插件决定盖什么。

### 7.8 主题插件示例

1. 安装插件，配置页选择背景图片、主色、圆角；
2. 宿主显示预览；
3. 用户选择「仅本会话」或「全局」；
4. 应用后聊天背景变化，输入区、气泡可读性由宿主校验；
5. 一键重置，卸载自动还原。

限制：不能注入 CSS/JS；图片必须经宿主选择或 HTTPS + 哈希；颜色需通过对比度校验。

### 7.9 恋爱游戏插件示例（验收用例）

1. 安装插件，配置角色、路线、背景包；
2. 插件注册 `sessionType`「恋爱游戏」；
3. 用户在新建会话时选择该类型，确认后创建**可删除**的专属会话；
4. 插件通过 `theme.apply` 改当前会话背景；
5. 每轮回复渲染 `choice` A/B/C + 自定义输入；
6. 插件把好感度、路线、旗标存自己的命名空间；
7. 删除会话或卸载插件时询问是否清理数据；
8. 主聊天、其它会话、记忆完全不受影响。

### 7.10 安全边界

1. 插件不能访问 `Android.*`、宿主 DOM、其它插件、其它会话。
2. 插件不能注入 HTML/CSS/JS；只能提交结构化组件、样式白名单和动作。
3. 组件、动作、样式、资源全部校验；未知类型降级，不执行。
4. 专属会话由宿主创建，插件只有自己命名空间的数据权限。
5. 插件不能修改系统提示词中的安全规则，只能增加人设。
6. 插件异常自动降级默认主题/默认会话，不影响聊天。
7. 全局主题、创建/删除会话、卸载清理、安装依赖都需要用户确认。
8. 适配器运行在沙箱，密钥由宿主保管，调用受配额与审计。

## 10. 执行步骤（按版本）

### 10.0 通用规则

每个版本固定走 10 步，不跳步：

```text
1 冻结范围 → 2 设计/ADR → 3 实现 → 4 自动测试 → 5 真机验证
→ 6 文档同步 → 7 构建与签名 → 8 发布与匿名回归
→ 9 生成工作转移包 → 10 复盘并更新本计划
```

规则：

- 每版只做一条主线；中途冒出的新想法记到「待排期」，不塞进当前版本。
- 每版启动前复核一次范围，允许调整，调整必须写进第 13 节变更记录。
- 紧急修复走 0.x.y 补丁版，不改变主线顺序。
- 每步完成即提交；提交信息写明步骤编号（如 `0.9/M3`）。
- **第 9 步必做**：`tools/handoff.sh` 生成工作转移包，产物在 `handoff/`（已 gitignore），
  包内含源码快照、workspace 文档、APK、git bundle、status/diff、SHA256SUMS 与恢复说明；
  工作随时可能转移，所以不等到最后一版才打包。

前置：0.7.2 已发布。目标：不加功能，把质量门补齐。

1. **N1 真机回归**：发送、粘贴、长按、横屏、音乐、设备、文件、公告、市场；

## 11. 验收与度量

每个版本发布前必须满足：

```text
核心聊天回归全绿
+ 上一版本功能不倒退
+ 自动化测试全绿
+ Release 签名可复现
+ 真机关键路径通过
+ 文档与市场索引一致
```

平台里程碑：

- 0.10：插件能注册宿主没写过的新页面/入口/会话类型/命令/后台任务，且不改宿主代码；v1 插件仍可运行；
- 0.11：主题插件、恋爱游戏插件、陌生功能插件（番茄钟）三个验收场景通过；
- 0.12：息屏 8 小时会话存活并可恢复；NapCat/Node/Mineflayer 可安装卸载；
- 0.13：MC 连续任务 30 分钟；
- 0.14：QQ 私聊/群聊稳定 24 小时、断线重连；
- 0.15：第三方不看源码能写出带页面、会话、主题、适配器的插件。
