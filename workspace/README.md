# 爱莉希雅项目工作文档区

这个目录专门保存项目过程文档和接手上下文，不放运行时代码。面向用户和发布审核的稳定技术文档位于项目根目录 `docs/`；构建产物位于 `release/`。

## 目录结构

```text
项目根目录/
├── docs/                          # 稳定技术文档、用户指南、发布说明
├── release/                       # APK、校验值和发布候选包说明
├── app/                           # Android 源代码和资源
└── workspace/                     # 过程文档和 AI 接手上下文
    ├── README.md
    ├── plans/                     # 当前计划与状态
    ├── discussions/               # 用户讨论结论
    ├── work-logs/                 # 实际检查、修改、构建和测试结果
    ├── decisions/                 # 已确认的长期决策
    └── issues/                     # 未解决问题和复现信息
```

## “讨论”和“工作”的区别

### discussions

记录用户提出的问题、双方讨论出的理解、产品取舍和待确认事项。

这里不能写成“已经修复”。例如：

```text
用户确认：Agent 工具调用不设固定硬上限，由设置项控制。
```

### work-logs

记录实际执行过的事情，例如：

```text
检查了哪些文件；发现了什么；构建是否成功；测试是否通过；有没有修改代码。
```

### decisions

记录用户已经明确确认的长期规则，例如：

```text
白名单继续作为硬限制；数据清除暂不改变；暂不上 Git 主仓库。
```

### plans

只放当前仍然有效的实施顺序。计划完成后要更新状态，不能让后来 AI 把计划误认为已完成。

## 用语规范

- 过程文档记录事实、条件、证据和状态，不将计划表述为完成结果。
- 稳定技术文档使用“组件、策略、能力、权限、接口、约束、验证”等术语，避免拟人化叙述。
- 用户界面中的角色化文案可以保留在应用资源和人设配置中，但不应进入技术文档和发布说明。

## 后续记录要求

每次和用户讨论后，新增或更新一份 `discussions`；每次实际工作完成后，新增一份 `work-logs`。如果讨论产生了稳定的产品决策，同时更新 `decisions` 和 `plans/current.md`。发布说明、用户指南和安全模型统一维护在根目录 `docs/`。
