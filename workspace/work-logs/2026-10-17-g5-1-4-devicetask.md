## G5-1 状态机 + 动作串行队列

### 新增（`03-state-tasks.js`）

```js
DEVICE_PHASES = { idle, orienting, planning, acting, verifying }
DEVICE_PHASE_TRANSITIONS = {
  idle: ['orienting','planning','acting'],
  orienting: ['planning','acting','idle'],
  planning: ['acting','idle'],
  acting: ['verifying','idle'],
  verifying: ['acting','orienting','idle']
}
```

- `deviceState(t)` 惰性初始化 `{phase, actionsUsed, failStreak, lastHash, lastAction, lastAt, readAt}`；
- `deviceSetPhase(id, phase, meta)`：非法迁移**不覆盖**当前相位，写 `invalid_device_phase` 事件并返回 false；
- `deviceReset(id)`：任务结束/取消时复位；
- `deviceBudget(t)` / `deviceBudgetLeft(t)` / `deviceGrantMore(t)`。

### 队列与并行（`11-plugin-engine.js`）

- 抽出纯函数 `planToolBatch(calls)` → `{ parIdx, serIdx }`：只读类进并行组，其余（含全部设备动作）串行组；
- 每批先 `Promise.all` 跑并行组，再按**原始下标顺序**逐个跑串行组；结果按原顺序回填；
- `canParallelTool()` 增加硬判定：设备动作永远返回 false；
- 非并行且非设备的调用（如写文件）保持原有顺序，不会被打乱；
- 事件 `device_queue` 记录 `{total, parallel, serial}`。

### 相位与计数收敛到单一入口

第一版把"进入 acting / actionsUsed++"写在工具循环里，导致直接调用 `execTool` 的路径不计数、
而 `failStreak` 又只在循环里递增 —— 两层各记一半。已全部收敛进 `execTool` 的设备动作分支：

```
预算检查 → 密码框门 → idle/planning 时自动 orient → acting → actionsUsed++
→ 执行 → verifying → 结构化验证 → 记录审计 → idle
```

循环里只保留"同动作同页面"的 `REPEATED_NO_CHANGE` 熔断（更严格的独立规则）。

## G5-2 读屏分级摘要 + 缓存 + 比例坐标

### 原生（`EllyAccessibilityService.kt`）

新增 `dumpScreenDigest()`，返回：

```json
{ "screen": {"w":1080,"h":2400,"density":2.75}, "count": 137,
  "nodes": [{ "t":"发送","x":920,"y":2210,"w":120,"h":90,
              "clk":true,"edt":false,"pwd":false,"scr":false,"foc":false,"cls":"Button" }] }
```

- `pwd` **只返回布尔**，不返回任何密码内容；
- 超限只体现为 `count` 与 `nodes` 长度差，**不抛错**；
- 旧的 `dumpScreenNodes()`（翻译在用）保持原样，互不影响；
- `PermissionBridge.getScreenDigest()` 暴露给 JS。

### JS（`07-media-tts.js`）

- `rawScreenNodes()`：优先新接口，老版本原生自动退化成旧接口 + `getScreenSize()`；
- `screenDigest({detail,page})`：
  - `basic` → `tier0`（可点击/可编辑/密码/可滚动，最多 40 项，带 `rx/ry/cx/cy`）；
  - `more` → 追加 `tier1`（文本行，最多 120 行）；
  - `full` → 追加 `tier2`（全量，20 项/页，带 `pages`）；
  - 超限只写 `note: "还有 N 项未列出"`，**永不失败**；
- 缓存：原始节点 3s 复用（重复读屏标 `cached:true, ageMs`）；
- **验证路径绕过缓存**（`screenFingerprint()` 用 `noCache`），并在动作后 `screenCacheClear()`——
  否则 2.5 秒内的页面变化会被 3 秒缓存吃掉，验证永远读到旧页面（这个坑测试抓到了）。

### 坐标

- 摘要给 `rx/ry`（相对屏幕中心，0~1，3 位小数）；
- `tap_screen` 接受 `rx/ry`，也兼容像素 `x/y`（>1 视为像素）；执行端换算并夹紧；
- `swipe_screen` 同样支持 `rx1/ry1 → rx2/ry2`；
- 工具 schema 与提示词已改为优先用比例坐标。

## G5-3 自适应验证

`deviceWaitChange(before)`：每 **150ms** 取一次指纹，变化即返回，上限 **2500ms**；
若变化后页面为空，再等 **600ms** 复查。

`agentVerifyAction(before)` 输出结构化结果并判定：

| verdict | 条件 | 处理 |
|---|---|---|
| `PASS` | changed && !empty | 正常继续，failStreak 清零 |
| `NO_CHANGE` | 未变化 | 给模型 warning；连续 3 次 → 暂停 |
| `EMPTY` | 变化但页面空 | `VERIFY_EMPTY`，计入失败 |
| `PACKAGE_DENIED` | 切到白名单外应用 | 立即停止任务 |

连续 3 次未生效 → `state: paused` + `VERIFY_REPEATED_FAIL`，**不判失败**，复位计数。

## G5-4 风险门与预算

### 密码框门（唯一风险判据）

- `input_text` 前查原生节点：`nodeIndex` 指定节点，或焦点可编辑节点；
- 该节点 `pwd === true` → `uiConfirm('要在这个密码框里输入吗？输入内容不会被记录…')`；
- 取消 → `USER_CANCELLED`，不执行；
- **不建任何关键词表**，普通输入不打扰。

### 预算

| 配置 | 默认 | 范围 |
|---|---|---|
| `deviceMaxActions` | 120 | 20~2000 |
| `deviceActionResumeChunk` | 120 | 20~2000 |

- 用尽 → `state: paused` + `BUDGET_EXHAUSTED`，**不判失败**；
- `taskResume` 检测到预算耗尽时自动补一批，并重置 deadline；
- 设置页「Agent 与手机控制」新增两个数字输入，纳入保存与结构回归。
